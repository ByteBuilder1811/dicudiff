# Security, threat model & limitations

## Scope (read this first)

DocuDiff is a **local, single-user tool**. It has **no authentication, no TLS, no user accounts and no tenant isolation**: anyone who can
reach the HTTP port can read, upload and delete every document. It has **not** been security-audited for production or internet exposure and
makes no such claim. Run it bound to localhost (the default for `uvicorn` and the Vite dev server). The audit behind this page is in
`docs/AGENT_D_FINDINGS.md`; every statement below is backed by code or a test in `backend/tests/test_security.py`.

## What is implemented

| Area | Behaviour (verified) |
|---|---|
| Upload size | `MAX_UPLOAD_MB` (default 25) is enforced by `SecurityMiddleware` **while the body is received** (Content-Length precheck plus byte counting for chunked bodies), so an oversized upload is cut off with 413 before the multipart parser spools it to disk. A second streaming check remains in the route. Non-upload JSON bodies are capped at 1 MB. |
| Upload content | Extension must be `.pdf` and the first bytes must be `%PDF-` (client `Content-Type` is ignored). Empty files give 422. Encrypted, zero-page, corrupt and over-`MAX_PAGES` PDFs are accepted as records with `status=failed` and a clear error, not parsed further. |
| File names | The client name is display-only: backslashes/paths are stripped, non-printable characters removed, length capped at 255. Files are stored as `<uuid>.pdf` in `DATA_DIR/uploads`. |
| Dedup | Identical bytes (SHA-256) are stored once. Concurrent identical uploads resolve to the same record (no 500, no orphaned file). Re-uploading with a different label **overwrites that document's label**. |
| Temp/orphan files | Temp file removed on every error path; a stored file is removed if ingest fails; stale `tmp-*` files older than 1 h are removed at startup. Document/comparison/report files are deleted **after** the DB delete commits. |
| Ids | Route ids must be ASCII alphanumeric, ≤40 chars. Downloads resolve only server-recorded generated names inside `DATA_DIR/reports`. |
| Retention | Deleting a document removes its file, pages, units, chunks/embeddings, every comparison using it, their changes and report files. `RETENTION_DAYS=N` purges older documents at startup (0 = keep forever). |
| Rate limiting | In-memory, per TCP peer address (X-Forwarded-For is not trusted). Two buckets: reads (GET) `RATE_LIMIT_READ_PER_MINUTE`=1200, so UI polling never trips it; everything else `RATE_LIMIT_PER_MINUTE`=60. Behind the Vite/nginx proxy all clients share one address, so it is effectively a global limit. State is lost on restart. |
| Host / Origin | `ALLOWED_HOSTS` allow-list on the `Host` header (localhost, 127.0.0.1, [::1], `backend` for docker; `*` disables) as a DNS-rebinding defence. POST/DELETE carrying an `Origin` not in `CORS_ORIGINS` (and not same-origin) get 403, which stops cross-site form posts to the local API. CORS allows only the listed origins, methods GET/POST/DELETE, no credentials. These are browser-side defences, not authentication. |
| Errors / logs | Unexpected exceptions return a generic 500 and are logged by exception **type only**; they are not re-raised, so no traceback is printed. Comparison failures store only a type name / fixed message and are retryable. Document text is not logged. (Failed ingest/extraction messages shown to the user contain exception type names only.) |
| Interrupted jobs | At startup, comparisons left `queued`/`running` by a previous process are marked `failed` (stage `interrupted`) and can be retried. Assumes a single server process. A job whose comparison is deleted mid-run stops quietly. |
| Timeouts | `COMPARISON_TIMEOUT_S` is **cooperative**: checked between stages only, a stage that hangs or runs long is not interrupted. PDF extraction is bounded separately (next row). LLM calls use `OLLAMA_TIMEOUT_S`. |
| PDF parsing isolation | Upload-time parsing (`extract_pdf_isolated`, used by `pipeline.ingest_pdf`) runs in a **child Python process**. The parent enforces a hard wall-clock limit (`EXTRACT_TIMEOUT_S`, default 120; the child's own page-loop budget is 80% of it so a slow-but-legitimate PDF degrades to a partial result before being killed) and a resident-memory ceiling (`EXTRACT_MAX_RSS_MB`, default 1500) by polling the child's RSS every ~100 ms (`/proc` on Linux, `ps` on macOS) and killing it when exceeded. On Linux the child additionally gets `RLIMIT_AS` = ceiling + 1 GB (not available/reliable on macOS, so there the watchdog is the only memory guard). On timeout, memory kill or crash the upload still succeeds as a document with `status=failed` and a clear error; the API server keeps running (tests: `tests/test_hardening.py`). **Limits of this:** the watchdog polls, so a parser that allocates several GB within 100 ms can overshoot the ceiling before being killed (set a container/cgroup memory limit as well; `docker-compose.yml` uses `mem_limit: 3g`); the child has no seccomp/filesystem sandbox, it runs with the server's privileges (the Docker image now runs as an unprivileged user); each upload pays ~2-4 s of interpreter + PyMuPDF start-up. `ISOLATE_EXTRACTION=false` parses in-process (debugging only). The comparison stage (diff/embeddings) is *not* process-isolated. |
| Optional API token | If `DOCUDIFF_API_TOKEN` is set, every `/api/*` request except `/api/health` must send `Authorization: Bearer <token>` (constant-time compare, 401 otherwise). Default empty = off (unchanged behaviour). This is a **minimal shared secret, not user authentication**: no accounts, no per-user audit, no TLS (the token travels in clear text unless you terminate TLS in front), no brute-force lockout beyond the rate limiter. The bundled frontend does not send the header; use a reverse proxy that injects `proxy_set_header Authorization "Bearer <token>";` (and add TLS there) or call the API with a client that sets it. Cross-origin browser calls would also need `Authorization` added to the CORS allowed headers (not done). |
| Response headers | `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer` on all API responses; report downloads are `attachment` with `Content-Security-Policy: sandbox`. |
| Reports | HTML report escapes document text, labels, file names, inline-diff spans and AI fields. **Known gap:** section labels (`old_section`/`new_section`, derived from heading text) are interpolated unescaped in `reporting.to_html`; this is mitigated only by the download being an attachment with CSP `sandbox`. PDF output escapes via reportlab. Markdown output is not escaped (a document can inject Markdown/HTML into a `.md` report; low risk, rendered by whatever viewer you use). |
| Prompt injection | Evidence is passed to the local LLM inside `<document_excerpt>` blocks with `<`/`>` replaced; the system prompt says excerpts are untrusted data; the model has no tools and cannot take actions; `[E#]` citations are validated against the evidence list and unknown ones are stripped with a warning. This **reduces** but does not eliminate injection risk: a small local model can still be swayed to give a wrong answer. AI output is always labelled and never changes the deterministic category. |
| Network egress | The backend contacts only `OLLAMA_URL` (default localhost). Embedding models load with `local_files_only` unless `ALLOW_MODEL_DOWNLOAD=true`. If you point `OLLAMA_URL` at a remote host, document excerpts are sent there. Frontend/dependency installation obviously uses the network. |

## Known limitations / not done

- No authentication, authorisation, TLS, audit log, encryption at rest (SQLite and PDFs are plain files in `DATA_DIR`), or multi-user isolation.
- **Docker:** `docker-compose.yml` publishes ports as `127.0.0.1:8000:8000` / `127.0.0.1:8080:80`; the image binds `0.0.0.0` inside the container. Changing the published address exposes the API to your LAN: set `DOCUDIFF_API_TOKEN` and add TLS in a reverse proxy if you do.
- PDF parsing uses PyMuPDF (native C library). It now runs in a killable child process with a time and memory watchdog (see table), so a crash, hang or memory blow-up no longer takes the API server down. It is **not** a security sandbox: a memory-corruption exploit in MuPDF would still execute with the server's privileges. Memory limiting is by polling (overshoot possible) and, on macOS, without `RLIMIT_AS`.
- Rate limiter and "interrupted job" recovery assume one process; they are not correct with multiple uvicorn workers.
- Cooperative timeout only (see above). SQLite is single-writer; heavy concurrent writes will queue or fail with "database is locked".
- Dependency scans were run once (see `docs/HARDENING_NOTES.md`); they are point-in-time and not part of CI.
- AI output may be wrong; Markdown reports are unescaped; HTML report section labels unescaped (see above).
