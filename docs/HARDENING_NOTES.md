## Known issues / remaining

- Isolated parsing costs ~2-4 s per newly uploaded PDF (child interpreter + `import pymupdf`, which in PyMuPDF 2.0 pulls in the layout package). A persistent worker would remove it but was not built.
- Memory watchdog polls every ~100 ms; large instant allocations can overshoot. macOS has no `RLIMIT_AS` guard.
- The comparison stage is not process-isolated.
- The three `tests/test_rag.py` failures seen in one full run (`test_invalid_or_missing_citations_are_flagged`, `test_model_output_ids_are_validated_even_if_injection_wins`) belong to files edited concurrently by another agent (`rag.py` is outside this task's ownership); see the final pytest output in the report for the state at the end.
- Existing tests modified: `test_security.py::test_failed_ingest_leaves_no_orphan_file` now patches `pipeline.extract_pdf_isolated` (ingest no longer calls `extract_pdf` directly); `test_reporting.py::test_pdf_non_latin_text_is_not_silently_garbled` adapted to the new `_pdf_font` signature/limitation wording.
- Files touched outside the listed ownership (minimal): `app/api/routes.py` (token dependency on the router), `tests/test_security.py`, `tests/test_reporting.py`.
